# Interview Project Summary

把实习或工作项目总结成面试讲解文档。

## 核心原则

**决策过程 > 流水账**

面试官关心三件事：
1. 你**为什么**做这个选择（不是做了什么）
2. 你**考虑了什么**替代方案（放弃了什么）
3. 你**学到了什么**（思维转变）

不要写成："然后我做了A，然后做了B，然后做了C"
要写成："我选择做A，因为考虑了X和Y，放弃了Z，原因是..."

## 何时使用

- 实习结束前总结项目
- 面试前准备项目讲解
- 项目结束后回顾提炼

## 何时不用

- 写日报/周报（那是流水账）
- 写技术文档（那是另一个skill）
- 写项目提案（那是未来的事）

## 六段标准结构

### 1. 项目概览

**必须回答**：谁、什么、为什么、怎么限制

| 要素 | 内容 |
|------|------|
| 客户/场景 | 谁在用？ |
| 目标 | 要解决什么问题？ |
| 限制条件 | 时间、技术、范围约束 |
| 最终产出 | 交付了什么？ |

### 2. 技术深度

**必须回答**：你理解了什么别人不一定理解的

重点不是列出技术名词，而是讲清楚**概念之间的关系**：
- 关键概念区分（比如 A vs B 的本质区别）
- 架构层次（系统是怎么分层的）
- 核心原则（贯穿始终的设计思想）

**模板**：用对比表讲清楚概念区别
```
| 维度 | A | B |
|------|---|---|
| 本质 | ... | ... |
| 执行者 | ... | ... |
| 调试方式 | ... | ... |
```

### 3. 决策过程

**必须回答**：做了什么选择、为什么、放弃了什么

每个决策按这个结构写：

```
### 决策 N：[决策名称]

**初始状态**：[之前是什么样]
**选择**：[做了什么]
**原因**：[为什么这样做]
**放弃的方案**：[考虑了什么但没选]
**效果**：[做完后怎样]
```

**常见决策类型**：
- 精简/删除（为什么去掉某些内容）
- 串联设计（为什么用这种方式连接各部分）
- 视角选择（为什么从某个角度切入）
- 技术选型（为什么选A不选B）

### 4. 挑战与解决

**必须回答**：遇到什么问题、怎么解决的

每个挑战按这个结构写：

```
### 挑战 N：[挑战名称]

**问题**：[具体是什么困难]
**解决**：[怎么解决的]
**效果**：[解决后怎样]
```

**常见挑战类型**：
- 概念混淆 → 一句话定性
- 内容层级不对 → 调整到目标受众能理解
- 结构缺乏串联 → 加过渡/因果连接
- 比喻/表达混淆 → 换更直接的说法

### 5. 最终产出

**必须回答**：交付了什么

- 技术特性清单
- 内容/功能结构
- 核心设计逻辑

### 6. 个人收获

**必须回答**：学到了什么、思维怎么变了

分三个层面写：
1. **技术层面**：对某个框架/工具/模式的理解
2. **设计层面**：对叙事/结构/用户体验的理解
3. **本质层面**：对某个领域核心问题的理解

## 面试讲解层次

### 30秒版（电梯演讲）

结构：`背景 → 技术理解 → 核心决策 → 产出`

要求：一口气讲完，不展开任何细节

### 3分钟版（面试回答）

结构：`背景(30s) → 技术理解(60s) → 决策过程(60s) → 核心原则(30s) → 产出(30s)`

要求：每个部分一句话总结，面试官追问再展开

### 追问应对

准备 3-5 个高频追问的回答：
- 技术实现细节
- 为什么选A不选B
- 最大的教训是什么
- 如果重做会怎么改

## 反模式

### ❌ 流水账
"首先我做了X，然后做了Y，最后做了Z"

**改为**："我选择做X，因为..."

### ❌ 只写做了什么
"创建了13页HTML幻灯片"

**改为**："从25页精简到13页，关键决策是删除Slide 7，因为..."

### ❌ 技术名词堆砌
"使用了HTML/CSS/JavaScript，暗色主题，响应式布局"

**改为**：解释为什么选择这些技术，解决什么问题

### ❌ 没有个人收获
整篇只讲项目，不讲你学到了什么

**改为**：每段收获都要有"之前我认为...现在我认为..."

### ❌ 六段都平均分配
每段写差不多长

**改为**：决策过程和挑战与解决是重点，应该最长；概览和产出可以短

## 模板

参考 [template.md](./template.md) 中的通用占位符模板。新项目按占位符填入内容即可。

## 工作流程

1. 读取项目相关的所有材料（代码、文档、对话记录）
2. 提取关键信息填入 template.md 的占位符
3. 补充决策过程和挑战与解决（这是最难也最重要的部分）
4. 编写 30秒/3分钟讲解版本
5. 准备追问应对
6. 将文档保存或提交到指定位置
