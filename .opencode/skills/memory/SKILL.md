# 跨会话记忆（含治理）

跨会话持久化用户偏好，支持智能治理：知识复合、证据分级、漂移检测、自动整合。

## 记忆文件

双作用域，项目覆盖全局：

| 作用域 | 路径 | 用途 |
|--------|------|------|
| 全局 | `~/.config/opencode/memory.json` | 通用偏好（语言、沟通风格） |
| 项目 | `.opencode/memory.json` | 项目特定偏好（运行时、测试框架） |

> JSON 格式、字段定义、日期获取方式详见 `references/format-spec.md`，写入 memory 前必须先读取。

## 证据分级

| 证据 | 来源 | 基础权重 |
|------|------|----------|
| `validated` | 用户明确表述（触发短语） | 1.0 |
| `observed` | Agent 观察到的模式（3+ 次） | 0.7 |
| `hypothesis` | Agent 推测（不确定） | 0.4 |

**自引用折扣**：Agent 提取的记忆（无触发短语）额外 ×0.5 权重，防止幻觉强化。

## 优先级分级

| 级别 | 含义 | 加载策略 |
|------|------|----------|
| **P1** | 永久偏好 | 每次会话始终加载 |
| **P2** | 活跃项目上下文 | 与当前项目相关时加载 |
| **P3** | 临时状态 | 仅在显式请求时加载 |

**自动分配**：用户说"以后总是" → P1；项目/任务相关 → P2；不确定/临时 → P3；默认 P2。

## 主干流程

### 1. 会话启动

1. 读取全局 + 项目 memory.json
2. 加载 P1（始终）+ P2（项目相关时）
3. 更新 `last_accessed`，递增 `session_count`
4. 检查 auto-dream 触发条件
5. 简要确认："已加载 N 条记忆（X P1, Y P2）。"
6. 静默应用偏好

文件不存在或为空时静默跳过。

### 2. 会话中自动提取

**触发短语**：记住、以后、总是、我喜欢、不要用、remember、always、I prefer、don't use

| 场景 | 证据 | 动作 |
|------|------|------|
| 用户明确表述 | `validated` | 自动保存，播报："已记住：你偏好 X" |
| Agent 观察到模式（3+ 次） | `observed` | 询问确认后再保存 |
| Agent 推测（单次） | `hypothesis` | **禁止自动保存**，必须询问确认 |

### 3. 写入记忆（知识复合）

1. **先搜索**：查找相似 key 或关键词重叠的事实
2. **找到相似**：合并更新 value，保持或提升 evidence 级别
3. **未找到**：检查容量（50 条上限），追加新事实
4. 默认全局作用域，仅明确项目相关时用项目作用域

> 漂移检测公式、权重计算详见 `references/drift-detection.md`

### 4. 记忆管理

支持自然语言操作："列出记忆"、"忘记 X"、"检查记忆"、"清理记忆"等。

> 命令列表和输出格式详见 `references/examples.md`

### 5. 冲突解决

- 项目 > 全局，明确告知用户
- 同作用域内：`validated` > `observed` > `hypothesis`，相同证据则较新的 `ts` 优先

## 关键规则

- **禁止**存储 API 密钥、令牌、密码等敏感信息
- **禁止**自动保存 `hypothesis` 证据 — 必须先询问用户
- **禁止**修改 AGENTS.md 或其他配置文件 — memory 是独立存储
- 每条 value 保持一句话以内
- 每次加载/使用记忆时更新 `last_accessed`（用于漂移检测）
- 优先更新已有事实，而非创建新事实（知识复合）

> 完整规则清单和错误处理详见 `references/rules.md`
