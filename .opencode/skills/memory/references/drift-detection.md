# 漂移检测与容量管理

## 漂移检测

加载记忆时，根据陈旧程度计算权重：

| 距 `last_accessed` 天数 | 漂移系数 | 状态 |
|------------------------|----------|------|
| 0-30 天 | 1.0x | 当前有效 |
| 31-60 天 | 0.8x | 可能过时 |
| 61-90 天 | 0.5x | 大概率过时 |
| 90+ 天 | 0.3x | 建议清理 |

### 权重计算

```
基础权重 = 证据权重 × 来源系数
  证据权重: validated=1.0, observed=0.7, hypothesis=0.4
  来源系数: 用户明确表述=1.0, agent提取=0.5

距今 = (now - last_accessed) / 86400000
漂移系数 = 1.0 (≤30天), 0.8 (≤60天), 0.5 (≤90天), 0.3 (>90天)

最终权重 = 基础权重 × 漂移系数
```

### 行为

- 列表展示时按 `最终权重` 降序排列
- 低权重记忆（< 0.5）放在末尾并标注警告
- 主动提供清理建议："3 条记忆超过 90 天未访问，是否要检查并清理？"

## 容量管理

- 每个文件最多 50 条事实
- **接近上限时**：自动触发整合（auto-dream）
- **整合后仍满**：移除最低权重的事实（按 `最终权重`），通知用户
- 用户想保留的话，建议使用项目作用域或通过"清理记忆"手动处理

## 自动整合（Auto-dream）

**触发条件（必须同时满足）**：
1. 距 `last_consolidation` 至少 24 小时
2. `session_count` ≥ 5

**整合流程**：
1. 查找重复项（语义相似）并合并
2. 移除低权重事实（最终权重 < 0.3）
3. 频繁访问的事实（10+ 次）提升为 P1
4. 更新 `last_consolidation` 为当前时间，重置 `session_count` 为 0
5. 播报："自动整合：合并 X 条重复，移除 Y 条过时，提升 Z 条为 P1。"

**手动触发**：用户可请求"检查记忆"来运行整合检查。
